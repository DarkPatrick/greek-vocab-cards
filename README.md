# Greek Vocabulary Cards + Codex / Claude CLI

Мини-проект для автоматической генерации печатных карточек по современному греческому.

Каждый запуск:

1. читает локальный `data/processed.csv`;
2. читает локальный снимок частотности `data/frequency.csv`;
3. пропускает уже обработанные исходные формы и известные словоформы;
4. берёт следующие 10 самых частых ещё не покрытых греческих токенов;
5. вызывает локальный `codex exec` или `claude -p` (backend выбирается в `config.json` / `--backend`);
6. требует структурированный JSON через JSON Schema;
7. по умолчанию запускает второй независимый проход той же модели для проверки;
8. создаёт по одному A4-friendly HTML-файлу на лемму и не дублирует его для разных словоформ;
9. только после успешной генерации обновляет CSV-состояние.

## Почему не БД

Для линейного процесса «частотный список → уже обработано / ещё не обработано» CSV проще:
его легко открыть глазами, поправить, положить в Git и распечатать/экспортировать.

## Установка

Нужны Python 3.9+ и установленный Codex CLI или Claude Code CLI (с выполненным входом).

Создай окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Убедись, что Codex доступен и ты уже вошёл:

```bash
codex --version
codex
```

Из интерактивного Codex после первого входа можно выйти — проект использует `codex exec`.

## Первый безопасный запуск

Сначала только посмотреть, какие слова выберутся:

```bash
python run.py --dry-run
```

При первом запуске автоматически создастся `data/frequency.csv`
из локальных данных пакета `wordfreq`.

Затем сгенерировать 10 карточек:

```bash
python run.py
```

Другой размер партии:

```bash
python run.py --count 5
```

Через Claude Opus 5.5 вместо Codex:

```bash
python run.py --backend claude
```

Постоянно переключить backend — поле `"backend"` в `config.json` (`"codex"` или `"claude"`);
модель и effort каждого backend лежат в `backends.<name>`. Разово сменить модель: `--model <id>`.
Партия из 2 слов (генерация + проверка) на Opus 5.5 с effort `high` занимает около 3,5 минуты.

Без второго проверочного прохода:

```bash
python run.py --no-verify
```

Пересобрать локальный частотный снимок:

```bash
python run.py --rebuild-frequency --dry-run
```

## Что лежит где

```text
data/frequency.csv   # локальный снимок частотности
data/processed.csv   # журнал уже созданных карточек
data/known_forms.csv # словоформы, которые уже покрыты карточками
output/*.html        # отдельные печатные карточки
prompts/*.md         # генератор и независимый проверяющий prompt
schemas/*.json       # строгая схема ответа модели
config.json          # размер партии, backend, модели, effort и т.п.
```

## Печать

Открой любой `output/*.html` в Chrome/Firefox/Safari → Print.
CSS уже настроен на A4 landscape.

HTML здесь удобнее Markdown:
- предсказуемая ширина таблицы;
- нормальная печать кириллицы и греческого;
- не нужен LaTeX;
- не нужен отдельный PDF-движок;
- при желании браузер сразу сохранит страницу в PDF.

## Важное ограничение частотности

`wordfreq` ранжирует **словоформы/токены**, а не идеальный учебный список лемм.
Поэтому проект дополнительно хранит `known_forms.csv`: после создания карточки
все возвращённые моделью `lexical_form` исключаются из будущего выбора.

Это сильно уменьшает повторы вроде разных падежных форм одного существительного,
но не является полноценной морфологической лемматизацией всего частотного корпуса.

Если несколько токенов одной партии после генерации получают одинаковую лемму,
сохраняется одна наиболее полная карточка. Если лемма уже встречалась в прошлой
партии, новый токен связывается с существующим HTML-файлом.

Для глаголов таблица отдельно показывает лицо, число и время/вид формы. Обычная базовая карточка
полностью перечисляет лица и числа каждого включённого временного ряда. Совпадающая написанная форма
занимает одну строку, а все её грамматические употребления перечисляются внутри этой строки.
Для глаголов с полной парадигмой генератор дополнительно проверяет матрицу из шести лиц/чисел
в настоящем, имперфекте, аористе и двух будущих временах. Для `είμαι`, `έχω` и безличного
`πρέπει` используются явно описанные исключения. Длинные карточки печатаются на нескольких страницах
с повтором заголовка таблицы.

Все карточки сгенерированы в текущем формате (генерация + независимая проверка моделью).
Это не заменяет вычитку носителем/преподавателем: ручные замечания лежат в `audits/`.

Если позже захочется академически строгий список именно **лемм**, достаточно
заменить `data/frequency.csv` своим CSV с колонками:

```csv
rank,source_word,zipf
1,....
2,....
```

Остальной проект менять не нужно.

## Почему два прохода Codex

Первый проход генерирует формы и примеры.
Второй получает уже готовый JSON и обязан заново проверить:

- lemma;
- род/число/падеж;
- окончания;
- ударения;
- артикли и согласование;
- естественность примеров;
- транслитерацию;
- русский перевод;
- отсутствие архаичных или придуманных форм.

Это не превращает LLM в безошибочный словарь, но заметно снижает риск тихих ошибок.

## Перегенерация одной карточки

```bash
python scripts/regenerate_existing.py έχω έχω --tenses present,imperfect,future_continuous --backend claude
```

Перегенерировать диапазон карточек на месте (те же файлы и леммы; порядок — как в `scripts/audit_batch.py`):

```bash
python scripts/regenerate_range.py --start 31 --count 56 --backend claude --workers 4
python scripts/regenerate_range.py --start 31 --count 56 --only υπάρχω --backend claude  # повтор отдельных
```

У каждой формы 1–4 примера (поле `examples`): у многозначных неизменяемых слов — по примеру на каждое значение.
Глаголы с ограниченным набором лиц перечислены в `PERSON_EXCEPTIONS` (`src/greek_vocab/main.py`);
формы других лиц у них отбрасываются автоматически.

Удалить карточки по лемме (файлы, записи в `data/*.csv`, нумерация сдвигается без пропусков;
во время генерации скрипт откажется работать):

```bash
python scripts/delete_cards.py νι            # план
python scripts/delete_cards.py νι --apply    # выполнить
```

Однобуквенные токены (ν, μ, σ' …) в партию не попадают.

## Безопасность запуска

Codex вызывается с:

- `--ephemeral`;
- `--sandbox read-only`;
- `--output-schema`;
- `--output-last-message`.

Claude вызывается с `-p --output-format json --json-schema`, без инструментов (`--tools ""`),
без MCP (`--strict-mcp-config`), без сохранения сессии и из пустой временной папки.

Модель ничего не редактирует в проекте сама.
Файлы пишет только Python-скрипт после проверки структурированного ответа.
